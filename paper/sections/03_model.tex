\section{Context Policies and Update Protocols}
\label{sec:model}
Let $P$ denote persistent task instructions, $o_t$ the current observation, and $H_{<t}$ the retained interaction records preceding it. The record includes observable messages and tool results; the notation makes no assumption about access to hidden model reasoning. A full-history policy constructs
\begin{equation}
 C_t^{\mathrm{full}}=[P,H_{<t},o_t].
 \label{eq:ctx-transcript}
\end{equation}
For structured state $\Sigma_t$, the replacement policy is
\begin{equation}
 C_t^{\mathrm{state},k}=[P,\Sigma_t,\tau_k(H_{<t}),o_t],
 \qquad \tau_0(H)=\varnothing,
 \label{eq:ctx-state}
\end{equation}
where $\tau_k$ selects the configured recent-history window, clipped at the start of the task. Full history is a separate reference policy, not state with an unlimited window. Figure~\ref{fig:architecture} shows the information retained by these policies.

\subsection{Who writes the state?}
In model-written memory, the model maintains semantic state $S_t$ through explicit updates. Hybrid memory separates this content from a runtime record:
\begin{equation}
 \Sigma_t=(S_t,V_t),\qquad
 S_{t+1}=\operatorname{Apply}(S_t,\Delta S_t),\qquad
 V_{t+1}=\operatorname{Record}(V_t,a_t,r_t).
 \label{eq:ownership}
\end{equation}
The recorder derives entries from observed tool events $r_t$; the model cannot edit those entries through its semantic patch. This ownership distinction does not guarantee complete capture or correct interpretation of every event. The evaluated hybrid variants differ in whether failed-attempt records are included. Recent history is an independent addition to either state family.

\subsection{How is an update coupled to an action?}
A separate update tool lets the model submit a state patch through the tool interface. An inline protocol instead asks for a joint envelope containing $\{\Delta S_t,a_t\}$, following the form of the published SKILL.state contract~\citep{skillstate2026}. These protocols differ in the relationship between state maintenance and environment actions; a tool-mediated policy step need not correspond to a single model invocation.

Algorithm~\ref{alg:context} specifies the context and ownership abstraction used to distinguish the policies. Its $\operatorname{PolicyStep}$ leaves message serialization and the number of tool-mediated calls unspecified; with full history it emits an action and leaves $S$ unchanged. Algorithm~\ref{alg:inline} describes the joint patch--action contract, including rejection before action execution. It is a reference contract for the comparison, not a recovered execution trace or a claim that every evaluated implementation obeyed every detail. A fixed retry count or automatic fallback to full history is not assumed.

\subsection{Context size and complete-task cost}
If interaction records have bounded size and the number of model calls per action is bounded, retaining the full transcript gives prompt growth of order $t$ and cumulative input growth of order $T^2$ over $T$ actions. A state policy has an action-independent context bound only when the state, observation, and retained-history records are all bounded. Under those assumptions and fixed $k$, cumulative input grows as $O(T)$. Neither statement fixes how many actions the policy will take to finish.

Let $U$, $K$, and $O$ be accumulated uncached-input, cache-read, and output tokens. With their respective tariffs $\alpha$, $\gamma$, and $\beta$, normalized cost is
\begin{equation}
 D=\alpha U+\gamma K+\beta O.
 \label{eq:cost-model}
\end{equation}
A smaller maximum prompt does not determine any of these task-level sums. State updates can add output, and a changing prompt can alter cache reuse; these are possible explanations to examine, not consequences proved by the context-size bound. The evaluation therefore reports success, prompt size, token categories, and cost separately.
